# DECISION-BRIEF — H-9 (destino do banco local `:5432`)

**Tier C** (reset/destruição de dados) · emitido pelo MAESTRO em 2026-09-16 · **bloqueante para:** `db:test` no container padrão, BATERIA-5432 (trilha 3.3).

## CONTEXTO

- O container `preco-que-da-lucro-postgres` (`127.0.0.1:5432`, `preco_que_da_lucro_test`) contém dado **não-fixture**: o down da migration `0010` aborta com **"2 conta(s) presentes"** e `db:purge-fixtures` aborta com **"8 usuário(s) fora do marcador de fixture `@preco-que-da.test`"**.
- Os guards são **fail-closed por desenho** (dado real ⇒ proibido purgar/rollback) e **não foram burlados**: as duas últimas rodadas rodaram `db:test` (11 e 13 suítes) em **containers efêmeros PG17** criados para o gate e removidos ao fim.
- Consequência prática: o `:5432` é hoje um banco de teste que **não aceita** a suíte completa; todo gate de DB custa ~1 min de container efêmero.

## DECISÃO EXATA

Escolher o destino do dado e do container: **(A)** reset destrutivo, **(B)** manter com efêmero, **(C)** dump → reset → manter dump arquivado.

## OPÇÕES

| opção                                             | custo  | risco                                                                                          | destravamento                                                     |
| ------------------------------------------------- | ------ | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| **A — reset** (`docker compose down -v && up -d`) | ~1 min | **perde o dado não-fixture** (irreversível)                                                    | `db:test` roda no container padrão; some a dependência de efêmero |
| **B — manter + efêmero** (status quo)             | 0      | nenhum (o dado fica intacto)                                                                   | nenhum novo; o custo de ~1 min por gate permanece                 |
| **C — dump → reset → arquivar**                   | ~3 min | o dump contém dados possivelmente pessoais ⇒ exige destino local com cuidado (nunca commitado) | `db:test` no padrão **e** dado preservado em arquivo local        |

## RECOMENDAÇÃO

**C** se o dado tiver valor de arqueologia (contas de homologação, probes de auth); **B** se for resíduo de teste — nesse caso recomendo **A** apenas depois de confirmar que nada em `docs/evidence/**` depende dele (nenhuma evidência desta rodada depende).

## CRITÉRIOS DE ACEITE

- Se `A`/`C`: `npm run db:test` **exit 0** rodando no `:5432` (sem efêmero).
- Se `B`: decisão registrada no `REGISTRO-H.md` e o container permanece intocado.
- Em qualquer caso: **nenhum** dado do `:5432` sai da máquina; nenhum dump é commitado.

## RUNBOOK

```bash
# (C) arquivar antes de resetar — destino local, NUNCA no repo
mkdir -p ~/.local/share/pi-fronts/pg-dumps
docker exec preco-que-da-lucro-postgres pg_dump -U postgres -d preco_que_da_lucro_test \
  > ~/.local/share/pi-fronts/pg-dumps/preco_que_da_lucro_test-$(date -u +%Y%m%dT%H%M%SZ).sql
# (A/C) reset
docker compose down -v && docker compose up -d --wait
# validar
DATABASE_URL=... npm run db:test
```

## ROLLBACK

Reset é **irreversível** sem dump ⇒ só escolha `A` sem backup se o dado for descartável. Com `C`, restaurar é `psql < dump.sql` no container novo.

## DESTRAVA

Higiene local; permite rodar a suíte de DB sem container efêmero e elimina uma fonte de confusão ("por que o guard recusou?").
