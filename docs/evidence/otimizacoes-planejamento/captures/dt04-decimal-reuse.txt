# DT-04 — constantes Decimal (2026-10-20)

> **Errata do instrumento (2026-10-21):** o registro original desta captura usava um padrão **BRE**
> (`grep -rn 'new Decimal(0|1|100)'`), em que `|` é **literal** e `(`/`)` são literais. Esse padrão
> **só casa com o texto literal `new Decimal(0|1|100)`** — nunca com `new Decimal(0)`,
> `new Decimal(1)` ou `new Decimal(100)`. O "vazio" da linha 4 original era, portanto, **vacuidade do
> instrumento**, não ausência de instanciações. A verificação foi **reexecutada com ERE real** (o
> instrumento agora **pode reprovar**), e o resultado real está abaixo. Verificação de vacuidade e
> reexecução: 2026-10-21.

## 1. O instrumento anterior (BRE) — vacuidade demonstrada

```
$ grep -rn 'new Decimal(0|1|100)' src/lib src/server --exclude=decimal-constants.ts
(saída vazia; exit 1)
```

**Controle de vacuidade** — o mesmo padrão BRE contra a string que ele próprio descreve:

```
$ printf 'const x = new Decimal(0|1|100);\n' > /tmp/kilo/bre-probe.txt
$ grep -n 'new Decimal(0|1|100)' /tmp/kilo/bre-probe.txt
1:const x = new Decimal(0|1|100);
```

O BRE casa **apenas** com o literal `new Decimal(0|1|100)`; contra `new Decimal(0)` — que existe no
repositório — ele **não** casaria. Logo, o "vazio" original **não provava** nada: o instrumento era
**vacuoso** (não podia falhar).

## 4. Definição congelada

import Decimal from "decimal.js";

/**
 * Constantes compartilhadas do motor financeiro (DT-04).
 *
 * `Decimal` é imutável em todas as operações públicas: métodos como `plus`,
 * `mul` e `div` devolvem novas instâncias e nunca mutam o receiver. Reutilizar
 * `0` e `1` elimina alocações repetidas nos laços de margem, ponto de
 * equilíbrio e impostos — e `Object.freeze` impede que um chamador futuro
 * trate-as como acumuladores mutáveis.
 */
export const DECIMAL_ZERO = Object.freeze(new Decimal(0));
export const DECIMAL_ONE = Object.freeze(new Decimal(1));
