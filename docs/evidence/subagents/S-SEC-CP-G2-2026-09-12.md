## Finding

**P1 — conjunto publicado está incompleto contra o item 11; publicar como está quebra chat e e-mails
de autenticação.** Evidência de contrato e de código:

- `docs/runbooks/hpanel-homologacao.md:17` exige **presentes** no runtime web:
  `DATABASE_URL`, `DATABASE_DRIVER=node-postgres`, `BETTER_AUTH_*`, `AUTH_TRUSTED_ORIGINS`,
  `RESEND_*`, `AI_GATEWAY_*`.
- Estado real do arquivo: `RESEND_*` → **nenhuma** chave (`RESEND_API_KEY`, `AUTH_EMAIL_FROM`
  ausentes) → requisito do item 11 **não satisfeito**; `AI_GATEWAY_*` → só `AI_GATEWAY_URL`, sem
  `AI_GATEWAY_API_KEY`; `BETTER_AUTH_*` → só `BETTER_AUTH_SECRET`, sem `BETTER_AUTH_URL`;
  `AUTH_TRUSTED_ORIGINS` ausente.
- Consequências de runtime, verificadas no código:
  - `src/lib/chat.functions.ts:226-227`: sem `AI_GATEWAY_API_KEY` (e sem o fallback
    `LOVABLE_API_KEY`, também não presente no arquivo) → `throw new ApplicationError("DEPENDENCY_ERROR")`
    — `/api/chat` falha; encosta no item 8 da homologação.
  - `src/server/email/email-adapter.server.ts:66-72`: sem `RESEND_API_KEY` **e** `AUTH_EMAIL_FROM` →
    `getEmailAdapter()` lança "obrigatórias para e-mails de autenticação" — chamado por
    `src/server/auth/auth.server.ts:44,53` (reset de senha / verificação de e-mail).
  - `src/server/auth/auth-policy.ts:38-44`: com `NODE_ENV === "production"` e `BETTER_AUTH_URL`
    ausente → `throw new Error("BETTER_AUTH_URL é obrigatória em produção")`, no caminho de auth de
    `src/server/auth/auth.server.ts:16`. O repo exercita o artefato de Hostinger justamente com
    `NODE_ENV: "production"` (`scripts/check-hostinger-runtime.mjs:96`); se o Web App do hPanel rodar
    o artefato em modo produção, o primeiro deploy sobe sem o par `BETTER_AUTH_URL`/`AUTH_TRUSTED_ORIGINS`.
    A ausência de `BETTER_AUTH_URL`/`AUTH_TRUSTED_ORIGINS` **é declarada como intencional** (cabeçalho,
    linha 2, "definidos PÓS-DEPLOY com o host final"), o que é defensável para preview — mas então a
    ordem "publicar envs → deploy → definir `BETTER_AUTH_URL` → redeploy" precisa estar explícita, e
    não se pode afirmar item 11 `PASS` antes disso.
- **Menor correção:** antes de publicar, decidir e registrar por escrito o conjunto do preview
  (inclusão de `AI_GATEWAY_API_KEY`, `RESEND_API_KEY`, `AUTH_EMAIL_FROM` e do par
  `BETTER_AUTH_URL`/`AUTH_TRUSTED_ORIGINS` com o host de preview, ou exclusão justificada com o
  impacto acima documentado). Não é violação do CP-G2 (nada proibido presente, nada vazio), mas é
  contradição direta com o requisito "presentes" do item 11 se o arquivo for a fonte da publicação.
