### Findings

**P1 — `docs/runbooks/dia-d-2026-09-12.md:197-203` (probe de auth): a alegação de prova é falsa; um `BETTER_AUTH_URL` obsoleto passa verde.**
Evidência: (a) `src/server/auth/auth-policy.ts:35-45` só exige que `BETTER_AUTH_URL` **exista e seja uma origem https pura** — `https://<preview-host>` satisfaz; (b) `src/server/auth/auth.server.ts:16,20` injeta esse valor como `baseURL`; (c) `node_modules/better-auth/dist/api/middlewares/origin-check.mjs:44` — `originCheckMiddleware` **retorna cedo em GET/HEAD/OPTIONS**, logo `GET /api/auth/get-session` não é validado contra `baseURL`/`trustedOrigins`: num host sem cookie a resposta é 200 `null` qualquer que seja o `baseURL` válido. O runbook ainda lista o preview host no conjunto confiável durante a transição (`§1.2`), então a "prova adicional" por `POST` também não discrimina (origin check valida o header `Origin`, não o `baseURL`). Impacto real: `baseURL` derivam URLs de e-mail (`sendResetPassword`, `auth.server.ts:43`; `sendVerificationEmail`, `:52`) e callbacks — o dia-D pode carimbar PASS com links de reset apontando para o preview. Fix mínimo: rebaixar a redação para o que é provado ("a instância de auth subiu com uma `BETTER_AUTH_URL` https válida; ≠200 ⇒ ABORT continua correto") e acrescentar uma asserção que discrimine o **valor**, ex. host do link de reset (já existe critério "e-mail de reset não chegando" em §3-0h) ou endpoint que emita URL absoluta derivada de `baseURL`.

**P2 — `ADR-028:32` (§2.1) e `engines-reconciliation-2026-09-12.md` §3: "EBADENGINE fatal, exatamente como no root" é asserção, não medição.** O FAIL reproduzido é do root declarado (`01-node-version.md:10-14`); o comportamento de `engine-strict` sobre nó `devOptional` (`package-lock.json:8681`) não foi exercitado (a própria evidência §4 admite remedição não executada). Fix mínimo: marcar como hipótese a confirmar por §8.2 e registrar o resultado (moot sob D3-i).

**P2 — `docs/runbooks/dia-d-2026-09-12.md:287` (GAP-DOC do R3): "`git revert`/`reset` + push" inclui operação proibida.** `reset`+push em branch publicada é rewrite de histórico — vedado por `AGENTS.md §Branching` / ADR-017, e §5.6 (linha 397) só menciona `git revert` + push. Fix mínimo: remover "reset" ou restringi-lo a branch descartável local.

**P2 — `docs/runbooks/dia-d-2026-09-12.md:33-34` (regra herdada) contradiz os blocos do próprio runbook.** A regra é citada como "todo passo executa via **npm script** ou pela UI/console oficial", mas §1.1 usa `mkdir`/`env|grep`, §1.1 usa `dig`, §1.3 usa `git rev-parse`, §1.6 usa `curl`/`smoke:substrate` — nenhum é npm script (só `smoke:substrate` é). A fonte original (`cutover-A4.md:12-16`) é escopada a caminhos **com guard** (banco/env) e há categoria sancionada "probe de monitoramento" (`cutover-A4.md:20-24`). Fix mínimo: reescrever a regra com o escopo original (mutações de DB/env via npm script; probes read-only sancionados).

**P2 — `ADR-028 §8.2`: a via (ii) não tem passo de prova correspondente.** §8.2 prova só D1+D3-i; para a via mínima o análogo é o log de build do alvo com o override ativo. Fix mínimo: uma linha alternativa em §8.2.
