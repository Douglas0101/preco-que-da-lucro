## 6. ACHADO EXTRA (nao era o alvo da fase): a telemetria nao chega a nenhum coletor no servidor compilado
Medido com um coletor OTLP local de mentira (`.artifacts/bughunt-a/otlp-sink.mjs`, 127.0.0.1:19099,
registra method/url/bytes) e um preview extra na :4176 apontando para ele:

- **Servidor compilado** (`.output/server/index.mjs`): **ZERO** requisicoes OTLP em ~2 min e 4
  requests HTTP (um deles com query no Postgres => span de DB). Com `NODE_DEBUG=http` (braco :4178)
  nao ha NENHUMA conexao de cliente HTTP — so trafego de servidor. O exportador nunca tenta sair.
- **Mesmo codigo em contexto de fonte** (tsx, `.artifacts/bughunt-a/otel-probe.mts`): 4 POSTs
  `/v1/traces` (2.199 B cada) + 3 POSTs `/v1/metrics` (2.048 B) em ~4 s.
- O SDK **inicia** no servidor compilado (com `OTEL_LOG_LEVEL=debug`: "EnvDetector/ProcessDetector/
  HostDetector found resource", "@opentelemetry/api: Registered a global for metrics v1.9.1" e
  "...for trace v1.9.1") => nao e falha de inicializacao; e entrega silenciosa.
- No bundle do servidor, `@opentelemetry/api` esta EMPACOTADO
  (`.output/server/_libs/opentelemetry__api.mjs`, importado pelo chunk `_ssr/client.server-*.mjs`)
  e os pacotes do SDK **nao** estao no bundle (sao carregados em runtime por specifier bare:
  `import(/* @vite-ignore */ "@opentelemetry/sdk-node")`) => DUAS copias da API no mesmo processo
  (medido: `bundled.trace !== node_modules.trace`; a API recusa o registro duplicado — diag medido
  "Attempted duplicate registration of API: trace").
- O app obtem tracer/meter NO TOPO DO MODULO, antes de o SDK registrar o provider; o proprio codigo
  do repo descreve esse modo de falha para as metricas
  (`src/instrumentation/telemetry.ts:456-466`: "continua emitindo em instrumentos noop, e o
  PeriodicExportingMetricReader nem invoca o exporter"). Medido: meter obtido antes do SDK => NENHUM
  POST /v1/metrics; meter obtido depois => POST a cada ciclo.
- **O MECANISMO DA SILENCIA NO SERVIDOR COMPILADO NAO FOI PINCADO.** As sondas isoladas com as
  duas copias (nas duas ordens de import) PROPAGARAM o provider para o tracer do app — logo a
  duplicacao, sozinha, nao reproduz o silencio. O que resta sem prova e a combinacao exata.
- Consequencia pratica: a evidencia de OB-02/OB-03 do repo
  (`docs/evidence/otimizacoes-planejamento/captures/ob02-ob03-otel.txt`, "started=true / flushed")
  prova que o SDK SOBE e DRAINA, **nao** que algo chega ao coletor: apontado para o coletor local,
  o smoke do repo tambem entrega ZERO requisições.
