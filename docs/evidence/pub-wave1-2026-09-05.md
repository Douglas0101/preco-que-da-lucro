## 2. R5 — SonarCloud FAILURE: causa-raiz e fechamento

O resíduo R5-open do ledger (Sonar FAILURE no PR #24) foi diagnosticado com as
anotações do check run (34 anotações; gate: Reliability **D** e Security **B**
em New Code, exigido ≥ A):

| Causa                                          | Regra               | Onde                                                   |
| ---------------------------------------------- | ------------------- | ------------------------------------------------------ |
| Função sempre retorna o mesmo valor            | S3516 (Reliability) | `src/db/client.server.ts` `instrumentClientRoundTrips` |
| PATH herdado em `execFileSync`                 | S4036 (Security)    | `scripts/m02-state-check.ts`                           |
| `.sort()` sem compare function ×4              | S2871 (Reliability) | `scripts/m02-matrix.ts`                                |
| Complexidade cognitiva 16/17 (teto 15) ×2      | —                   | `scripts/m02-matrix.ts`                                |
| Literal duplicado em migration **já aplicada** | S1192               | `drizzle/0008_*.sql`                                   |

Correção publicada (PRs #26/#27): retorno `void` na instrumentação; PATH fixo
(`/usr/local/bin:/usr/bin:/bin`); sorts com `localeCompare`; extração de helpers
(`isTypeOnlyImport`, `classifyServerFunction`, `collectOperation`,
`classifyTransactionSite`); e **`.sonarcloud.properties` com
`sonar.exclusions=drizzle/**`** — migrations aplicadas são imutáveis e
`drizzle/meta/*.json` soma ~29k LOC (cota Free de 50k, cf.
`sonar-pr7-remediation-2026-08-14.md`). Behavior-preservation do refactor de
`m02-matrix.ts` comprovada: saída do gerador byte-idêntica à do baseline em
worktree isolado de `origin/develop`.
